# 2026-08-31

## 修复：录屏产出 3KB 空壳 + 自检误报「音轨静音」

### 现象
用户勾选录屏播放 `动物与道德高度演讲视觉页面_自动播放.html`，产物只有 2.8KB / 2.1KB，
弹窗报「录到了音轨，但里面是静音数据 / 音轨峰值 0.0000 / 送入音轨数 1 / 产物含音轨 是」。

### 定位过程（关键：别信弹窗，直接解 MP4）
用 python 解 moov 得到：
- **只有 1 条 trak，hdlr=`soun`，完全没有任何 `vide` 视频轨**
- `stts entries=0`、`stsz sample_count=0`（0 个样本）
- `mvhd duration = 127ms / 85ms`
- mdat 仅 2048B / 1366B

结论：**不是音频问题，是录制在启动 100 多毫秒时就被停掉了**。
H.264/AAC 编码器初始化要几百毫秒，来不及吐样本 → 视频轨连 trak 都没建，
音频只留 stsd 里写着 mp4a 的骨架。旧自检用正则 `/mp4a|soun/` 判断「含音轨」→ **必然误报**。

### 根因
v3.1 直接全屏录屏：`setFullscreen(true)` → sleep 450ms → `getDisplayMedia`。
Electron 的 `setFullScreen()` 返回时窗口还在做样式重建 + DWM 重新合成（余波数百 ms~1s），
捕获源在余波末尾失效 → video track `ended` → `session.onExternalStop` resolve →
父层立刻 `send({type:'stopPlay'})` → `finishRecording()` → 成片只有 127ms。
（人不可能在 127ms 内手动停共享，所以只可能是自动路径。）

### 改动
1. `electron/main.cjs`：新增 `waitFullscreenSettled()`，`zt:set-fullscreen(true)` 改为
   await 等到 `enter-full-screen` 事件落地 + 250ms 余量才 resolve（2s 超时兜底；
   已是全屏则不再有事件，走 100ms 余量）。
2. `src/App.jsx` `handleStartPlay`：全屏落定后再 sleep 300ms 才建捕获。
3. `src/App.jsx`：`onExternalStop` 加 1.5s 保护窗 —— 起步 1.5s 内轨 ended 视为全屏余波误触发，
   **忽略并继续录制**（否则就是几 KB 空壳 + 把排查方向带偏到音频上）。
4. `src/App.jsx`：自检重写 —— 新增 `probeTracks()` 数 vide/soun 轨 + stsz 样本数；
   新增录制时长、首个数据块、MediaRecorder 错误、送入轨数(视/音)；
   录制 <1.5s 直接判「过短」并改报错文案；`probeAudioLevel` 在 <0.5s 时不再测电平
   （那时"静音"是果不是因）。
5. `src/recorder.js`：`stop()` 返回 `durationMs / recError / firstChunkMs`；
   `onExternalStop` resolve 出「距启动多少 ms」；启动日志补送入轨数。
6. 顺手修：`probeAudioLevel` 的 AudioContext 从未 close → 每次录制泄漏一个，
   内核约 6 个配额，录几次后 AudioContext 建不出来。

### 验证

- `npm run build` 通过；已 `rm -rf dist` 清理堆积（emptyOutDir:false，之前堆到 3 个 js）。
