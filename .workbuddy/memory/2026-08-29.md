## 定位并修复「选了擦除滑入，录屏出来是放大」

### 根因（不是绑定问题）
`editorRuntime.js` 的 `startPlay()` 里 `if (nativeScript && hasAudio)` 会走原生路径，
`injectNativePlayer()` 注入**页面自带的原始播放脚本**（App.jsx `getNativePlayerScript()` 抠出来的）。
那段脚本是**生成 HTML 那一刻的引擎快照**，效果表永远停在旧版本。

样例页（v5.1 生成）的 `getEffectKeyframes` 只有 9 种 → `wipe` 落进
`default: return {from:{transform:'scale(1)'},to:{transform:'scale(1.2)'}}` → 就是放大。
且旧 `playAnimation` 是 `fill:'forwards'` → 没设恢复时长时元素**永久停在 scale(1.2)**。

所以：**预览对（走 editorRuntime）、导出对（htmlProcess 每次重新生成）、唯独播放/录屏错**。
附带：`blur-in` 同样坏；`highlight-sweep` 在旧 loop 里没有分支 → 也掉进放大。
且旧 `playAnimation` 只取 transform/opacity，clipPath/filter 类效果物理上无法表达。

### 修复：动画引擎收敛到单一真源
新建 `src/animEffects.js`（效果清单 + 引擎源码切片），四端消费：
- `htmlProcess.js` 导出脚本嵌入 `animEngineSource()`
- `App.jsx` 下拉清单 + `ready` 时 postMessage 下发 `bootstrap`/`parts`
- `editorRuntime.js` 预览（`playBoundAnimation` 走引擎）
- `editorRuntime.js` `patchNativeEngine()`：**注入原生脚本前**用括号配对定位函数体，
  整体替换 `getEffectKeyframes` + `playAnimation`

关键设计：`playAnimation` 必须和 `getEffectKeyframes` 一起换，且**要么都成功要么都不换**
（半吊子补丁 = 新 keyframes 返回 null 撞上旧 playAnimation → 抛异常打死整条播放循环）。
新 `playAnimation` 内部先过 `applyStateEffect()`，因此 `highlight-sweep` 无需改 loop 就能对。

行为变更：未知效果从「默默放大」改为返回 null + `console.warn`，不再放大。
